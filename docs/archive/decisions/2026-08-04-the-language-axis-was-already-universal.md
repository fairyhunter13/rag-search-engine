# The language axis was already universal

**2026-08-04.** A deep survey was asked for: tree-sitter, LSP, and *every* option and alternative,
per language, so the engine supports any language, framework and structure. This records the survey
and its one shipped consequence, which is a four-word change to a `frozenset`.

The headline finding is not "tree-sitter is enough." It is that **the question is usually asked
about the wrong population.** Every published comparison of these tools is a statement about a
corpus, and this fleet's corpus is unusual in a way that inverts most of the published rankings.

Method, in the order doctrine requires — local population first, headline last:

1. **Local census**, 2026-08-04, all 155 `graph.db` stores (61,584 files): `file_extraction`
   grouped by language and rung.
2. **Local capability ceiling** — `docs/reference/grammar-capability-matrix.md`, generated by
   `scripts/gen_grammar_capability_matrix.py` against `tree-sitter-language-pack` 1.14.0.
3. **External rosters** — Sourcegraph's indexer table, GitHub stack-graphs, Glean/Kythe, Joern,
   multilspy, aider's repo map, ast-grep, and the per-language LSP field.

---

## 2. The option space, per tool class

### tree-sitter — shipped, and past what any competitor uses

`graph/extractor.py` (e1→e14) runs six rungs over the pack's 371 languages: `embedded` from the
grammar's own `injections.scm`, `structure` from the pack's typed `process()`, `_generic_walk`,
`highlights` from the grammar's own `highlights.scm` parent-kind filtered, `data`, then dark with a
recorded reason.

Worth stating plainly because it is the benchmark people reach for: **aider's repo map is rung 4
only** — `tags.scm` plus PageRank. The generated matrix says `tags` exists for **71 of 371**
languages, which is why this repo skipped a tags rung entirely and went to `highlights`
(**319 of 371**). And personalized PageRank over this same graph was built, measured and **reverted**
(`2026-08-03-personalized-pagerank-was-built-and-reverted.md`), then re-closed on 2026-08-04 when
R1's edges landed without moving it.

Per-language ceilings come from the matrix, not from a survey: php/javascript/vue/html/markdown/
nginx/rust reach rung 1; typescript/tsx/go/python/java/c/cpp/csharp/kotlin/ruby reach rung 4;
css/scss/less/sql/bash/yaml/json/xml/gherkin/dockerfile/make reach rung 4; **groovy, jinja2 and hcl
ship no query files at all** and are rung 6 by construction.

### LSP — declined, and for a stronger reason than the one first given

`2026-08-04-the-residual-has-no-types-to-resolve.md` governs. `scip-php` on **two** Laravel roots
(the second chosen specifically to falsify the first) recovered **0 of 718** ambiguous call sites
against a 25% gate. Cost was never the issue — 2.55 s, 71 MB RSS. It names `self::`, `$this->` and
global calls at 20–90%, *precisely the calls that were never ambiguous*, and reads **0.0%** on
`$var->` receivers, which are the whole problem. The residual is untyped at the source, so every
type engine has the same nothing to say.

The batch route does exist, and the old "LSP has no batch API" objection was wrong (it measured LSP
against a workload nobody proposed). **multilspy** (Microsoft, NeurIPS 2023 artifact) is a
language-agnostic LSP client library in Python covering Python, Rust, Java, Go, JavaScript, Ruby,
C#, Dart — **it covers none of php, vue, groovy or typescript**, i.e. it misses every language where
this fleet has a gap.

One entrant post-dates the pilot and is the only "revisit if" worth writing down: **PHPantom**
(Rust, on the Mago parser) claims closure-parameter inference from generic context, PHPStan
conditional return types and array-shape inference — mechanisms scip-php genuinely lacks. It is
LSP-only with no batch mode or index export, early-stage, and infers *from annotations*, which the
residual receivers do not carry. Gated below, not scheduled.

### SCIP / LSIF — the coverage arithmetic is decisive

Sourcegraph's GA roster is Go, TypeScript/JavaScript, C/C++, Java, Scala, Kotlin, Rust, Python,
Ruby, C# — ten languages, and **PHP is not on it**. `scip-php` is third-party MIT whose tagged
releases stop at v0.0.2 (April 2023), needs `:dev-main`, and needs `composer install` plus a
populated `vendor/` **per root** across 208 repositories — against an `IGNORED_DIRS` entry the repo
already decided (`2026-08-04-the-vendor-prize-buys-edges-nobody-reads.md`). `scip-typescript` does
**not** index Vue SFCs (`vue-tsc`/Volar is a type *checker*; it emits `.d.ts`, not a symbol index).
No Groovy indexer exists in any of these formats.

Against this fleet's ~41,900 code files:

| | files | share of code |
|---|---:|---:|
| covered by a **GA** SCIP indexer (js, go, ts, tsx, python, java) | 11,446 | **27%** |
| **php + vue + groovy — no indexer in any format** | 27,130 | **65%** |

A per-language toolchain, a per-root build and a working compiler for each — to reach a quarter of
the corpus, in the languages that are *already* the best-extracted (go 2.1% dark, tsx 7.3%,
python 18.6%).

### The rest

- **stack-graphs** — real `.tsg` implementations exist for Python, TypeScript/JavaScript, Java and
  Rust only; GitHub's own precise navigation shipped two and the promised additions did not broadly
  arrive. **0%** of this fleet's php/vue/groovy mass, and strictly dominated by SCIP where it
  overlaps.
- **Joern / CPG** — ~12 frontends and the only class offering real *dataflow* rather than name
  binding, which this repo genuinely lacks. Same wall: dataflow tracks a value to its origin, and
  the residual's origin is itself untyped, so the chain terminates naming no class. JVM/Scala,
  GB-scale RSS, minutes per repo, against `2026-08-04-denying-the-daemon-swap.md`.
- **Kythe / Glean** — storage and query layers that *ingest* other people's indexers. Adopting
  either means adopting the section above plus a second database. `graph.db` + the `overview`/`graph`
  MCP tools already are that layer.
- **ctags / ast-grep / Comby** — ast-grep's own docs say it "does not have deep semantic
  information… only operates on the syntactic level"; universal-ctags is a regex-per-language
  vocabulary that aider migrated *off* to tree-sitter. Both are pattern vocabularies about source
  text, which P6/HR15 bans outright, and both are weaker than rung 3.
- **LLM extraction** — HR15 bans the escape hatch; HR10 confines `claude -p` to the dashboard.

## 3. The citation trap, and the dial this repo already owns

The survey returns a headline that looks decisive: on a 2M-line codebase, type-resolved reachability
scored **grep < tree-sitter (~0.3–0.5 recall) < SCIP (~0.97)**. That number is real. It is also the
fourth time this shape of citation has arrived here — after RepoGraph's CrossCodeEval EM, the
PageRank paper, and the `$ref` prevalence claim. All were directionally real and locally wrong, and
two named the wrong language.

Two things dissolve it:

1. **Benchmarks of type-resolved reachability run on statically typed corpora.** This fleet is 37%
   PHP, much of it CodeIgniter 3, where the pilot measured **0.0%** of ambiguous receivers carrying
   any type. The gap that benchmark measures does not exist here to be closed.
2. **Our measured recall is already 0.633, above the cited tree-sitter band — and the trade is a
   dial, not a ceiling.** From `_MAX_CALLEE_FANOUT` (`daemon/sweeps.py`), over 155 stores and
   193,309 call-site groups:

   | cap | edges | precision | recall |
   |---:|---:|---:|---:|
   | **1 (shipped)** | 122,324 | **1.000** | 0.633 |
   | 2 | 157,854 | 0.887 | 0.725 |
   | 4 | 193,176 | 0.780 | 0.779 |
   | none | 1,021,043 | 0.182 | 0.960 |

   Most of the recall an external type engine would buy is **already reachable by turning this
   knob**, and the repo turned it the other way deliberately, because `graph_handler` has no
   confidence column and cannot distinguish a resolution from a guess. That is a product decision,
   and if it is ever re-litigated it should be re-litigated as one — not by installing a type engine.

## 4. The one real defect: every `.txt` file was code

Verified live against pack 1.14.0:

```
detect_language("CMakeLists.txt")   -> vimdoc
detect_language("requirements.txt") -> vimdoc
is_code_language("vimdoc")          -> True
```

The pack's `detect_language_from_path` maps the `.txt` **extension** to vimdoc; `detect_language`
returns it unchallenged, and `is_code_language` answers True because the pack has the grammar. Three
silent consequences across **390 fleet files** (354 at rung `generic`, 36 `language_mismatch`, 0
symbols between them): they take the 500 kB `code` size cap instead of the 200 kB `text` one; they
feed `_code_source_fingerprint`, so **editing a `requirements.txt` could wake a graph re-derive**;
and they sit in H1's coverage denominator (`code_files_extracted`) as permanently dark code.

That is the csv/po incident of 2026-07-31 recurring in a language that fix did not cover. Fixed the
same way — `vimdoc` joins `_TEXT_LANGS` — with `EXTRACTOR_REV` bumped e13 → e14 **in the same
commit**, because `index/discover.py` is not in `_FINGERPRINT_MODULES` and a classification change
moves no stamp on its own.

The other 40 languages were audited in the same pass and **none moved**. The audit's own correction
is the part worth keeping: `scss` looked like an obvious sibling of the already-excluded `css`, and
is not — it is only 60.9% dark and holds **673 symbols**, so reclassifying it would delete
extraction that works. And **100% dark is not the criterion**: `groovy` is 2,065 files at 100% dark
and is unambiguously code. The criterion is whether the language is prose or data.

## 5. Framework awareness: the rule exists, the build does not clear the bar

`2026-08-03-an-import-is-a-declared-fact.md` already fixes the only P6-legal test: the input must be
path arithmetic or a checked-in declarative manifest, never a table of framework knowledge this repo
maintains, and the answer must be falsifiable against the filesystem — emit only if the target
exists *and* is indexed.

That doc already refused Blade's `@extends('layouts.app')` under rule 1. **Laravel routes, DI
containers, ORM model conventions and config-driven dispatch fail rule 1 identically.** So "support
any framework" in its usual sense is not a gap in this engine — it is the thing HR15 exists to keep
out, and building it means overturning an invariant rather than adding a feature.

What *does* pass both rules is manifest-declared module aliasing: `_ImportResolver._js`
(`daemon/sweeps.py`) resolves relative paths only, so `@/components/Foo`, `~/lib` and workspace
packages are dropped, while `tsconfig.json` `paths`/`baseUrl` and `package.json` `workspaces` are
manifests. Measured before proposing it: across **232** candidate roots, **8** declare
`tsconfig`/`jsconfig` `paths` and **1** declares `workspaces` — and of those 9, only **3** are
indexed projects. Same shape as the declined `$ref` resolver (12 files) and the Tier-2
protobuf/graphql candidates (6 and 0). Recorded, not scheduled; re-open when an alias-driven root
lands, and the check is one `ls`, not a research pass.

## 6. Repo structure: no gap, one hygiene item

Discovery already handles polyglot and nested repos structurally — full `.gitignore` chain with
per-file mtime caching, `IGNORED_DIRS`, generated-code suffix screening, per-category size caps —
and the census confirms it with zero files in `no_grammar`/`unparsed`/`timeout`/`crashed`/`error`.

`no_language` (3,889 files, 6.3%) is the only residue, by basename: 1,740 per-host nginx vhost
files (a `*.<domain>.local` naming scheme, all in one workspace); 1,423 extensionless, of which
`Dockerfile` 55, `fastcgi_params` 43,
`Jenkinsfile` 38, `Makefile` 25, `LICENSE` 7, and the bulk `ci_session*` blobs; ~600 `.svx`/`.neon`/
`.dev`/`.template`/`.bak`/`.enc`/`.png` that are not source; and 40 `.ipynb`.

Confirmed against pack 1.14.0: `Dockerfile`, `Makefile`, `Jenkinsfile`, `Procfile`,
`fastcgi_params` and `*.local` all return `None` from `detect_language_from_path`, and the S7 shebang
fallback cannot reach them. **~118 recoverable files fleet-wide** is below every gate this repo has
applied, and the fix is exactly the filename→language table `detect_language`'s docstring already
declines. Left alone. The `ci_session*` blobs are corpus hygiene, not language —
`scripts/purge_unindexable.py` is the home, `2026-07-31-corpus-hygiene.md` the precedent.

## The rules this earned

- **A language's ceiling is a generated fact, not a survey.** "Which tool for language X" is
  answered by `docs/reference/grammar-capability-matrix.md`, regenerated after a pack upgrade — not
  by reading the tool's README.
- **Check a tool's language roster against the local census before its accuracy claim.** Every
  option in section 2 was eliminated by coverage arithmetic before accuracy was even reached. The
  accuracy debate is the expensive one and it was never needed.
- **A published recall figure is a statement about a corpus.** Before believing one, check whether
  the mechanism it measures exists in yours. Four times now it has not.
